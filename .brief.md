# Brief: Widen contact_inbox_projection coverage rule

## Problem

The current rule in `packages/domain/src/inbox-driving.ts` (function `isInboxDrivingCanonicalEvent`, exported alongside `isInboxDrivingEventType`) only creates a projection when the canonical event passes ALL of:

- `eventType` ∈ `{communication.email.{inbound,outbound}, communication.sms.{inbound,outbound}}`
- `provenance.inboxProjectionExclusionReason ≠ "forwarded_chain"`
- `provenance.sourceRecordType ≠ "internal_only_message"`
- `provenance.messageKind` is `"one_to_one"` OR (`null` AND a trusted provider/source-record combination)

This explicitly excludes `messageKind="auto"`, `messageKind="campaign"`, and ALL non-communication event types (lifecycle, campaign emails, internal notes). As a result, **5,469 of 6,767 contacts (~81%) with canonical events have NO projection row**, making the inbox unsearchable for most volunteers.

Verified prod-DB breakdown of the gap:

| Bucket | Count | Cause |
|---|---:|---|
| Has only campaigns | 3,687 | Rule excludes campaign events |
| Has only auto SF emails | 859 | Rule excludes `messageKind="auto"` |
| Has only lifecycle | 822 | Rule excludes lifecycle events |
| Anomaly: has 1:1 events but no projection | 94 | Separate latent bug; backfill (separate brief) catches them |

## New rule (architect-locked)

A contact gets a `contact_inbox_projection` row iff there exists ≥1 canonical event for the contact whose provenance has neither:

- `provenance.inboxProjectionExclusionReason = "forwarded_chain"`, NOR
- `provenance.sourceRecordType = "internal_only_message"`.

That is: every canonical `eventType` qualifies (communication, campaign, lifecycle, note), and every `messageKind` qualifies (one_to_one, auto, campaign, null) — only the two explicit exclusion reasons block.

## Field semantics (Tier 2)

The projection row's fields are derived from the contact's full canonical-event history (filtered to non-excluded events) as:

- `lastInboundAt` = newest `occurredAt` among `communication.{email,sms}.inbound` events. Stays nullable.
- `lastOutboundAt` = newest `occurredAt` among `communication.{email,sms}.outbound` events (regardless of `messageKind` — auto + 1:1 both count) ∪ `campaign.email.sent` events. Stays nullable.
- `lastActivityAt` = newest `occurredAt` of any qualifying event (lifecycle / campaign / note included). NOT NULL.
- `bucket` semantics unchanged: `"New"` only when `lastInboundAt` is newer than the operator-acknowledged-read mark; otherwise `"Opened"`. Lifecycle/campaign-only contacts default to `"Opened"`.
- `lastEventType` = the `CanonicalEventType` of the newest qualifying event. (DB column is already `canonicalEventTypeEnum`, the full 15-value enum — no migration needed.)
- `lastCanonicalEventId` = id of the newest qualifying event.
- `hasUnresolved` semantics unchanged.
- `needsFollowUp` semantics unchanged.

## Change

### 1. `packages/domain/src/inbox-driving.ts`

Replace `isInboxDrivingCanonicalEvent` with a new exported function `qualifiesForInboxProjection(event)`:

```ts
export function qualifiesForInboxProjection(
  event: Pick<CanonicalEventRecord, "provenance">
): boolean {
  const provenance = event.provenance;
  if (provenance.inboxProjectionExclusionReason === "forwarded_chain") {
    return false;
  }
  if (provenance.sourceRecordType === "internal_only_message") {
    return false;
  }
  return true;
}
```

Keep `isInboxDrivingEventType` as-is — it's still useful for code paths that legitimately want the narrow communication-only set (e.g. UI inbox-channel mapping). Audit each call site of `isInboxDrivingCanonicalEvent` and migrate to `qualifiesForInboxProjection`. Run:

…and update every call site appropriately. Do NOT delete `isInboxDrivingEventType`.

### 2. `packages/domain/src/normalization.ts`

In two places, the apply/rebuild paths use the old rule:

- `applyInboxProjection` (around line 2096): the early-return when the event isn't projection-driving. Update to use `qualifiesForInboxProjection`. The field derivations also need updating per Tier 2:
